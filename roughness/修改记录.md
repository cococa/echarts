# Roughness 手绘风格功能修改记录

## 修改日期
2025-01-22

## 修改概述
修复了 ECharts 手绘风格（roughness）模式下的多个问题，包括：
1. 修复了黑色填充覆盖整个图表区域的问题
2. 实现了折线图的手绘效果
3. 修复了 SVG 渲染模式的兼容性问题
4. 修复了柱状图的手绘效果

## 详细修改内容

### 1. 修复 ClipPath 导致的黑色填充问题

**问题描述：**
在 roughness 模式下，X轴和Y轴扫过的区域被黑色斜线填充覆盖（x: 108, y: 59, width: 614, height: 452）

**根本原因：**
ClipPath 矩形被应用了 roughness 效果，导致裁剪区域被绘制成手绘填充

**修改文件：**
- `zrender/src/canvas/graphic.ts`
- `zrender/src/graphic/shape/Rect.ts`

**解决方案：**

1. **在 `zrender/src/canvas/graphic.ts` 的 `updateClipStatus` 函数中：**
   - 在绘制 clipPath 之前临时将其 roughness 设置为 0
   - 绘制完成后恢复原始 roughness 值
   - 这样确保裁剪路径不会被应用手绘效果

2. **在 `zrender/src/graphic/shape/Rect.ts` 的 `buildPath` 方法中：**
   - 添加 `isClipPath` 检查：`const isClipPath = !!(this as any).__clipTarget;`
   - 当元素是 clipPath 时，跳过 roughness 绘制
   - 作为额外的保护层

3. **在 `zrender/src/handdrawn/RoughCanvas.ts` 中：**
   - 修改 `_drawFillOps` 方法，跳过白色和透明填充
   - 避免不必要的填充绘制

---

### 2. 实现折线图的手绘效果

**问题描述：**
折线图（ECPolyline）虽然有 `roughness=2.6` 属性，但没有显示手绘效果

**根本原因：**
- ECPolyline 的 `buildPath` 方法接收的是 `PathProxy` 对象而不是真实的 `CanvasRenderingContext2D`
- PathProxy 是用于路径缓存的代理对象，无法直接应用手绘效果
- 手绘效果需要直接在真实的 canvas context 上绘制

**修改文件：**
- `zrender/src/canvas/graphic.ts`
- `echarts/src/chart/line/poly.ts`
- `echarts/src/chart/line/LineView.ts`

**解决方案：**

1. **在 `zrender/src/canvas/graphic.ts` 的 `brushPath` 函数中：**
   ```typescript
   // 如果元素有 roughness，直接绘制而不使用 PathProxy
   if (el.roughness) {
       console.log('=== brushPath: drawing with roughness directly ===', {
           type: el.type,
           roughness: el.roughness,
           hasStroke: hasStroke,
           hasFill: hasFill,
           strokeColor: style.stroke,
           fillColor: style.fill
       });
       ctx.save();
       ctx.beginPath();
       el.buildPath(ctx as any, el.shape, inBatch);
       
       if (hasStroke) {
           doStrokePath(ctx, style);
       }
       if (hasFill) {
           doFillPath(ctx, style);
       }
       
       ctx.restore();
       el.__dirty = 0;
       el.__isRendered = true;
       return;
   }
   ```
   - 在创建 PathProxy 之前检查元素是否有 roughness
   - 如果有 roughness，跳过 PathProxy 系统
   - 直接调用 `buildPath` 并传入真实的 canvas context
   - 这样 ECPolyline 的 `buildPath` 就能接收到真实的 context 并应用手绘效果

2. **在 `echarts/src/chart/line/poly.ts` 的 ECPolyline 类中：**
   - 添加了 `buildPath` 方法中的手绘效果支持
   - 当接收到真实的 CanvasRenderingContext2D 时，使用 rough.js 绘制手绘折线
   - 将点数组转换为 `[x, y]` 格式并调用 `rc.linearPath(pointArray)`

3. **在 `echarts/src/chart/line/LineView.ts` 中：**
   - 添加了调试日志以追踪 ECPolyline 的创建和渲染过程

**关键代码：**
```typescript
// 在 ECPolyline.buildPath 中
if (this.roughness && !(ctx instanceof PathProxy)) {
    const pointArray: [number, number][] = [];
    for (let i = 0; i < points.length / 2; i++) {
        const x = points[i * 2];
        const y = points[i * 2 + 1];
        if (!isPointNull(x, y)) {
            pointArray.push([x, y]);
        }
    }
    
    if (pointArray.length > 0) {
        const stroke = typeof this.style.stroke === 'string' ? this.style.stroke : undefined;
        const rc = rough.canvas(ctx as any, {
            options: {
                roughness: this.roughness,
                stroke: stroke,
                strokeWidth: this.style.lineWidth || 1,
            },
        });
        rc.linearPath(pointArray);
    }
    return;
}
```

### 3. 修复 SVG 渲染模式的兼容性问题

**问题描述：**
在 SVG 渲染模式下出现错误：`Cannot read properties of null (reading 'beginPath')`

**根本原因：**
- 最初尝试通过跳过 PathProxy 创建来优化 canvas 渲染
- 但 SVG 渲染器依赖 PathProxy 来生成 SVG 路径
- 当 `el.path` 为 null 时，SVG 渲染器调用 `path.beginPath()` 导致错误

**修改文件：**
- `echarts/src/chart/line/poly.ts`

**解决方案：**
- 移除了 ECPolyline 中自定义的 `createPathProxy` 方法
- 让 PathProxy 始终被创建（SVG 渲染需要）
- Canvas 渲染通过 `brushPath` 函数中的 roughness 检查来绕过 PathProxy
- 这样两种渲染模式都能正常工作：
  - Canvas 模式：在 `brushPath` 中检测到 roughness 后直接绘制
  - SVG 模式：正常使用 PathProxy 生成 SVG 路径（roughness 不适用于 SVG）

### 4. 修复柱状图的手绘效果

**问题描述：**
柱状图（Bar Chart）的矩形没有应用手绘效果

**根本原因：**
- Rect 类的 `buildPath` 方法中，roughness 绘制只在有 fill 时才执行
- 没有处理 stroke（边框）的情况
- 缺少 stroke 和 strokeWidth 参数传递

**修改文件：**
- `zrender/src/graphic/shape/Rect.ts`

**解决方案：**
```typescript
if (this.roughness && !shape.r && !isClipPath && width > 0 && height > 0) {
    console.log('=== Rect.buildPath with roughness ===', {
        roughness: this.roughness,
        filler: this.filler,
        fill: this.style.fill,
        stroke: this.style.stroke,
        x, y, width, height
    });
    
    const fill = typeof this.style.fill === 'string' ? this.style.fill : undefined;
    const stroke = typeof this.style.stroke === 'string' ? this.style.stroke : undefined;
    
    if (fill || stroke) {
        const rc = rough.canvas(ctx, {
            options: {
                roughness: this.roughness,
                fillStyle: this.filler,
                fill: fill,
                stroke: stroke,
                strokeWidth: this.style.lineWidth || 1,
            },
        });
        rc.rectangle(x, y, width, height);
        return;
    }
}
```

**改进点：**
1. 同时支持 fill 和 stroke
2. 添加 stroke 和 strokeWidth 参数
3. 只要有 fill 或 stroke 就应用手绘效果
4. 添加调试日志

## 技术要点

### 1. PathProxy vs 真实 Canvas Context
- **PathProxy**：用于路径缓存和优化，是一个代理对象
- **真实 Context**：CanvasRenderingContext2D，可以直接绘制
- **Roughness 需求**：必须使用真实 context 才能应用手绘效果

### 2. 渲染流程
```
Element.render()
  → brushPath() [检查 roughness]
    → 如果有 roughness：直接用真实 ctx 调用 buildPath()
    → 如果没有：使用 PathProxy 缓存路径
```

### 3. ClipPath 处理
- ClipPath 用于裁剪，不应该有视觉效果
- 必须确保 ClipPath 不应用 roughness
- 两层保护：在 graphic.ts 中临时清除 + 在 Rect.ts 中检查

### 4. 多渲染器兼容
- Canvas 渲染器：支持 roughness 手绘效果
- SVG 渲染器：不支持 roughness，但不应该报错
- 解决方案：始终创建 PathProxy，但在 canvas 渲染时绕过它

---

## 已知限制

1. **SVG 渲染模式**：不支持 roughness 效果（SVG 本身的限制）
2. **圆角矩形**：带圆角的矩形（shape.r 存在时）不应用 roughness
3. **性能**：roughness 模式下性能略低于普通模式（因为跳过了路径缓存）
